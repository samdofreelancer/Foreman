# Foreman Board P1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Build the P1 OpenCode Desktop GUI plugin with a persistent four-column task board, create/edit/delete flows, project filtering, title search, and no session or database access.

**Architecture:** A single root TypeScript package builds one host-loaded `./gui-experimental` CommonJS bundle. Pure domain functions own Task validation, ordering, grouping, and filtering; SolidJS components translate the reactive `Store.global` state into the OpenCode SettingsPage UI and host calls. Host imports stay under `src/gui/`.

**Tech Stack:** TypeScript 5, SolidJS 1.9, Vite 7, `@opencode/plugin/gui/vite`, `effect` Schema, Vitest.

**Spec:** `specs/001-board/spec.md`

## Global Constraints

- Package name and plugin id: `foreman`.
- Dedicated SettingsPage id: `foreman`, reachable at `/settings?tab=foreman`.
- Command id: `foreman.open-board`; keybind `mod+shift+b`, navigation section.
- Columns are exactly `todo`, `ready`, `doing`, `done`, rendered Todo, Ready, Doing, Done.
- Persistence: `Store.global(Schema.Array(Task), [])`; never read or write the OpenCode database.
- P1 must not create, stop, prompt, or delete any OpenCode session.
- Host-provided modules are external; the build output is one `dist/gui-experimental.cjs` bundle under 200 KB.
- Card order is `updatedAt` descending, then `id` ascending.
- UI strings live in `src/i18n/en.ts`.

## Review Focus

- Corrupt, missing, or older store data must produce `[]` plus a visible dismissible warning; test reset behavior in `tests/task.test.ts`.
- Duplicate titles must remain distinct via stable ids; test two tasks with the same title in `tests/columns.test.ts`.
- Moving into and out of Done must set and clear `finishedAt` while leaving `id` and `createdAt` unchanged; test in `tests/task.test.ts`.
- Combined project filtering and title search must be intersection-based and leave column counts filtered; test in `tests/filters.test.ts`.
- Missing project directories must remain usable and surface a project-missing state in the card; verify manually with the desktop acceptance run.
