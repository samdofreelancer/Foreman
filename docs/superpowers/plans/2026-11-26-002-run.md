# Foreman Run P2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn Ready tasks into one OpenCode session, derive live Doing state, open/follow-up in that session, finish runs, and add drag-and-drop.

**Architecture:** Add a pure P2 decision layer for run state, start guards, and drop resolution. Keep host and client effects in `src/gui/run/` and `src/gui/board/`; P1's store remains the only local state, while session state is always derived from the sidecar reactive store.

**Tech Stack:** TypeScript 5, SolidJS 1.9, OpenCode GUI 2.x host API, OpenCode promise client, Vitest.

**Spec:** `specs/002-run/spec.md`

## Global Constraints

- Never write or read the OpenCode database directly.
- Never approve permissions or answer questions automatically.
- The sidecar server id is `sidecar`; session actions use `ctx.servers.get("sidecar")` and `ctx.tabs.open`.
- A task owns at most one session id; `sessionID` is set once and never replaced.
- Ready drop/session start and follow-up both originate from an explicit owner gesture.
- Prompt fallback is the task title when description is empty.
- Doing derives state from live session data: working, unread, reviewed, missing.
- Drag/drop on Doing is rejected; P1 dialog column selection remains the accessible alternative.
- Moving to Done sets `finishedAt`; moving out of Done clears it.
- Board re-renders state within 5 seconds and no polling faster than 3 seconds.

## Review Focus

- Double drops and rapid repeated Ready drops must create one session: test `canStart` and in-memory `starting` coverage in `tests/start-guard.test.ts`.
- Session creation success plus prompt failure must keep the session and expose retry: test `startTask` behavior in `tests/start-task.test.ts`.
- Live state must use busy/idle/viewed precedence and missing sessions neutrally: test `deriveRunState` in `tests/run-state.test.ts`.
- Moving a running task to Done must require explicit confirmation and cancellation must leave it in Doing: test drop resolution and manual Desktop acceptance.
- Follow-up delivery must queue only while working and never send empty text: test `buildFollowUpInput` in `tests/follow-up.test.ts`.
- Narrow-window and cancelled drags must leave stored state unchanged: test `resolveDrop` and manual acceptance.
